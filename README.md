# სართულების განაწილება მენეჯერებზე — რეპორტი

Bitrix24-ის (crm.archi.ge) **82 ლისტიდან** («მენეჯერი») აწყობს მატრიცას:
სვეტები = მენეჯერები (სახელი, Email, ნომერი, შიდა ნომერი), რიგები = პროექტები,
უჯრა = სართულების დიაპაზონები, რომლებზეც მენეჯერი პასუხისმგებელია (მაგ. `1 - 5, 21 - 26`).

## გახსნა

1. დააკოპირეთ `config.example.js` → `config.js` და ჩაწერეთ Bitrix24 webhook URL
   (`config.js` git-ში არ იდება).
2. ორმაგი კლიკი `index.html`-ზე (Chrome / Edge). სერვერი და ინსტალაცია არ სჭირდება.
3. საჭიროა ინტერნეტი: მონაცემები ყოველ გახსნაზე პირდაპირ Bitrix24-იდან იტვირთება,
   ხოლო შრიფტი (Google Fonts) და Excel-ბიბლიოთეკა (SheetJS) CDN-იდან.

## ფუნქციები

- **პროექტები / მენეჯერები** — multi-select ფილტრები ძებნით, «ყველას მონიშვნა» და «გასუფთავება».
- **სართული** — ჩაწერეთ ნომერი: მოინიშნება უჯრები, სადაც ეს სართული შედის, ზემოთ გამოჩნდება პასუხი
  «პროექტი: მენეჯერი». სხვა უჯრები მქრქალდება.
- **კონფლიქტი** — თუ ერთ პროექტში ერთ სართულზე ორი მენეჯერია, უჯრას წითელი ჩარჩო და `!` ბეჯი აქვს,
  პროექტის სახელთან წითელი წერტილია. დეტალები უჯრაზე მაუსის დაყოვნებით (tooltip).
- **სულ სართული** — ცხრილის ბოლო ხაზში მენეჯერის სართულების ჯამი ხილულ პროექტებზე (ფილტრზე რეაგირებს).
- **Excel export** — ხილული (ფილტრირებული) ცხრილი `.xlsx` ფაილად.
- **განახლება** — მონაცემების ხელახლა წამოღება გვერდის გადატვირთვის გარეშე.
- ბეჭდვა (`Ctrl+P`) — ფილტრების პანელი იმალება, იბეჭდება მხოლოდ ცხრილი.

## მონაცემების წყარო

| REST მეთოდი | რისთვის |
|---|---|
| `lists.element.get` (IBLOCK_ID 82) | ჩანაწერები, 50-50 გვერდობით |
| `lists.field.get` (IBLOCK_ID 82) | პროექტების ID → სახელი, ლისტის მნიშვნელობების ID-ები |
| `user.get` | მენეჯერების სახელი, Email, ტელეფონი, შიდა ნომერი |

ლისტის ველები:

| ველი | დანიშნულება |
|---|---|
| `PROPERTY_430` | პროექტი (ბმული 111 ლისტზე) |
| `PROPERTY_431` / `PROPERTY_432` | სართული-დან / სართული-მდე |
| `PROPERTY_986` | ყველა სართული (კი/არა) |
| `PROPERTY_433` | ლუწი / კენტი |
| `PROPERTY_434` | პასუხისმგებელი (თანამშრომელი) |
| `PROPERTY_1033` | floors(sorted) — მზა სართულების სია, **ძირითადი წყარო** |
| `PROPERTY_1357` | პროექტის სახელი ტექსტად (fallback) |

თუ `PROPERTY_1033` ცარიელია, სართულები ითვლება «-დან/-მდე» დიაპაზონით, ლუწი/კენტი ფილტრის გათვალისწინებით.

## Vercel-ზე გამოქვეყნება

ჰოსტინგზე `config.js` არ არის (git-ში არ იდება), ამიტომ გვერდი მოთხოვნებს აგზავნის `/api/bitrix`-ზე —
serverless proxy ([api/bitrix.js](api/bitrix.js)), რომელიც webhook-ს სერვერის ცვლადიდან იღებს. Webhook ბრაუზერში არ ჩანს.

1. Vercel → პროექტი → **Settings → Environment Variables**:
   - `BITRIX_WEBHOOK` = `https://crm.archi.ge/rest/USER_ID/WEBHOOK_CODE/` (Production + Preview)
   - სურვილისამებრ `BITRIX_IBLOCK_ID` (default `82`)
2. **Deployments → Redeploy** (ცვლადები მხოლოდ ახალ deploy-ზე მოქმედებს).

Proxy უშვებს მხოლოდ `lists.element.get`, `lists.field.get`, `user.get` მეთოდებს და მხოლოდ კონფიგურირებულ ლისტზე.
გაითვალისწინეთ: თავად გვერდი ღიაა ყველასთვის, ვისაც Vercel-ის ბმული აქვს. თუ შეზღუდვა გჭირდებათ,
გამოიყენეთ Vercel-ის Deployment Protection ან დაამატეთ ავტორიზაცია.

## კონფიგურაცია

- `config.js` — webhook URL, `iblockId`, `iblockType` (ლოკალური, git-ში არ იდება).
- `index.html`, `CONFIG.props` — ველების (property) ID-ები. სხვა ლისტზე გადასაყვანად მხოლოდ ეს შეცვალეთ.

## დამოკიდებულებები

| რა | საიდან | ვერსია |
|---|---|---|
| SheetJS (`xlsx`) — Excel export | cdnjs | 0.18.5 |
| Noto Sans Georgian | Google Fonts | — |
| Node runtime (მხოლოდ Vercel proxy) | Vercel | პლატფორმის default, `fetch` ჩაშენებული |
| Bitrix24 REST | crm.archi.ge webhook | scopes `lists`, `user` |

npm პაკეტები არ არის; `package.json` დაემატება ტესტებისთვის (იხ. docs/PLAN.md M3).

## ინსტალაცია / განახლება

- **ლოკალურად**: `git clone`, `config.example.js` → `config.js`, გახსენით `index.html`. განახლება = `git pull`.
- **Vercel**: push `main`-ზე → ავტომატური deploy. პირველ ჯერზე `BITRIX_WEBHOOK` ცვლადი (იხ. ზემოთ). Bitrix-ის მხარეს ინსტალაცია არ სჭირდება, არაფერი იწერება.
- ლისტის ველების ID-ების ცვლილებაზე: `index.html` → `CONFIG.props`.

## ცნობილი შეზღუდვები

- გვერდი ბმულით ღიაა, ავტორიზაცია არ არის (გადაწყვეტილება D-5).
- «ყველა სართული» = კი ჩანაწერებზე ნაჩვენებია მხოლოდ `floors(sorted)`-ში არსებული სართულები; პროექტის სართულების საერთო რაოდენობა ლისტში არ არის.
- `QUERY_LIMIT_EXCEEDED`-ზე ავტომატური retry არ არის, მხოლოდ «ხელახლა ცდა» ღილაკი.
- მობილურზე ცხრილი ჰორიზონტალურად სქროლდება, ცალკე მობილური განლაგება არ არის.
- ავტომატური ტესტები ჯერ არ არის (docs/PLAN.md M3).

## ⚠ უსაფრთხოება

Webhook-ის token `config.js`-ში ინახება. ვისაც ეს ფაილი აქვს, CRM-ში წვდომა აქვს იმ მომხმარებლის უფლებებით,
რომელმაც webhook შექმნა. `config.js` მხოლოდ შიდა გამოყენებისთვისაა: არ დადოთ საჯარო სერვერზე/რეპოზიტორიაში,
არ გაუგზავნოთ გარე პირებს. თუ token გავრცელდა, Bitrix24-ში webhook გააუქმეთ და ახალი შექმენით.

რეპოზიტორია საჯაროა, ამიტომ `config.js` `.gitignore`-შია. ჰოსტინგზე webhook მხოლოდ სერვერის
Environment Variable-ში უნდა იყოს (იხ. Vercel სექცია).
